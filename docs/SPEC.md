# 대입 면접 준비 앱 — 프로젝트 브리프 (Claude Code용)

> 이 문서는 시장조사 결과를 바탕으로 작성된 개발 지시서다. 새 레포의 `CLAUDE.md` 또는 `docs/SPEC.md`로 저장하고, 작업 시작 전 전체를 읽을 것.
> 작성일: 2026-09-23

## 0. 한 줄 요약

**대학별 공개 면접 기출 + LLM 예상질문 + 지원자 유형별(특성화고·검정고시·재수생·재외국민) 맞춤 답변 코칭** 웹앱. 1단계 목표는 "기출 검색 + 유형별 질문 템플릿 + 답변 코칭"까지이며, 음성/영상 모의면접은 후순위다.

## 1. 배경과 시장조사 결론 (왜 이렇게 만드는가)

### 1-1. 확정된 사실
- 모든 대학은 「공교육정상화법」 제10조에 따라 매년 3월 말 입학처 홈페이지에 **선행학습 영향평가 결과보고서**를 공개한다. 제시문 기반 면접·구술고사는 문항·출제의도·해설·채점기준까지 공개된다.
- **서류(학생부) 기반 면접과 인성면접은 문항 공개 의무가 없다.** 대다수 대학이 "문항카드 미작성"으로 처리하고 평가영역·예시질문만 낸다. 따라서 **"전국 모든 대학 실제 기출 DB"는 불가능**하다.
- 실제 문항을 공개하는 대학(1차 수집 대상): 서울대, 연세대, 고려대, 성균관대, 경희대, 중앙대, 서울시립대, 이화여대, 한국외대, 동국대, 인하대, UNIST, 한국에너지공대, 서울교대, 공주교대, 육군사관학교 등.
- 경쟁 서비스(몬스터T, 면접왕, 뷰인터 생기부, 유니고, 인앤써, 진학사 AI모의면접)는 전부 **"생기부 업로드 → AI 질문 생성 → 피드백"** 한 가지 구조다. 대학별 공개기출 큐레이션도, 지원자 유형별 특화도 없다.
- 시장: 2026학년도 수시 지원자 약 52만 명, 검정고시 등 기타 지원자 2.2만 명, 재외국민 특별전형 시행 대학 약 160개. 오프라인 면접 컨설팅은 회당 40~50만 원.
- 리스크: (1) 생기부는 미성년자 개인정보 덩어리 — 경쟁사 몬스터T도 2026년 7월 생기부 업로드 기능을 중단했다. (2) 대교협·대학 자료의 원문 재배포는 저작권 문제 소지. (3) 대형 입시업체 진입 가능.

### 1-2. 이로부터 도출된 설계 원칙 (반드시 지킬 것)
1. **생기부 원문은 서버에 저장하지 않는다.** 브라우저에서 파싱해 요약된 구조화 데이터만 세션 동안 사용하고, 사용자가 명시적으로 저장을 선택하지 않는 한 서버로 보내지 않는다.
2. **대학 보고서 원문 PDF를 앱에서 재배포하지 않는다.** 문항은 구조화·요약해 제공하고, 원문은 각 대학 입학처 링크로 연결한다. 모든 문항 레코드에 출처 URL과 연도를 남긴다.
3. **차별화 축은 "지원자 유형별 특화"다.** 일반고 3학년을 기본값으로 가정하지 말 것. 온보딩에서 유형을 먼저 묻는다.
4. **공개 문항이 없는 대학은 "유형 예측"으로 채운다.** 해당 대학 보고서의 평가영역·예시질문 + 같은 계열 타 대학 공개 문항을 근거로 LLM이 예상질문을 생성하고, 화면에 "실제 기출"과 "예상질문"을 명확히 구분 표시한다.
5. 만 14세 미만 이용자는 법정대리인 동의 플로우를 거친다. 연령 게이트를 회원가입에 넣는다.

## 2. 지원자 유형 정의 (핵심 도메인 모델)

| 코드 | 유형 | 면접에서 흔히 나오는 특화 질문 방향 |
|---|---|---|
| `GENERAL` | 일반고 재학생 | 학생부 활동 기반 (기본값) |
| `VOCATIONAL` | 특성화고·마이스터고 | 전공 실습 경험, 취업 대신 진학 선택 이유, 특성화고 전형 지원 동기 |
| `GED` | 검정고시 출신 | 학교 밖 학습 경험, 자기주도성, 공백기 활용, 학생부 부재 보완 |
| `REPEAT` | 재수·N수생 | 재도전 사유, 지난 1년의 변화, 성숙도 |
| `OVERSEAS_3` | 재외국민 3년 특례 | 해외 학교 경험, 한국 사회·학과 적응, 언어 |
| `OVERSEAS_12` | 재외국민 12년 특례 / 외국인 | 전 교육과정 해외 이수, 한국어 능력, 진학 동기 |
| `ALTERNATIVE` | 대안학교 출신 | 대안교육 경험의 의미, 일반 교육과정과의 차이 |

각 유형별로 **공통 질문 템플릿(10~20개)** 과 **답변 프레임(구조 가이드)** 을 시드 데이터로 준비한다. 템플릿은 `data/seed/profiles/{code}.json` 에 둔다.

## 3. MVP 범위 (Phase 1)

### 포함
1. **기출/예상질문 DB 검색**: 대학 → 전형 → 모집단위(계열/학과) → 연도 → 유형(제시문/서류기반/인성/전공/영어) 필터. 각 문항에 출제의도·해설(있으면)·출처 링크.
2. **지원자 유형 온보딩**: 유형·지원 대학·전형·학과·간단한 자기 정보(활동 3~5개 텍스트 입력, 생기부 업로드는 선택).
3. **맞춤 예상질문 생성**: 온보딩 정보 + 해당 대학 공개문항/평가영역 + 유형 템플릿을 LLM 프롬프트로 결합 → 예상질문 15~20개 (실제 기출 / 예상 구분 태그).
4. **답변 코칭**: 사용자가 답변을 텍스트로 입력 → LLM이 구조(두괄식·근거·경험·연결)·논리·길이·대학 평가요소 부합도를 피드백하고 개선 예시를 제시. 답변 저장은 로컬(IndexedDB) 기본, 서버 저장은 옵트인.
5. **생기부 클라이언트 파싱(선택 기능)**: PDF를 브라우저에서 텍스트 추출 → 활동 항목 요약 → 세션 메모리에만 보관. 서버 전송 없음. 사용자가 "요약만 저장" 선택 시 요약 텍스트만 저장.
6. **관리자 데이터 도구**: 대학별 PDF 수집·파싱·검수용 CLI 스크립트.

### 제외 (Phase 2 이후)
- 음성/영상 모의면접, 비언어 분석
- 결제·이용권 (Phase 1은 무료 베타 + 대기자 이메일 수집만)
- 컨설턴트 매칭, B2B 대시보드
- 모바일 네이티브 앱 (반응형 웹으로 대응)

## 4. 데이터 파이프라인 (가장 먼저 만들 것)

```
[1] 대학 목록·URL 시드 (data/seed/universities.json)
      ↓
[2] 수집기: 입학처 페이지에서 선행학습 영향평가 PDF / 기출 PDF 다운로드 (2022~2026학년도)
      ↓  raw/{univ}/{year}/*.pdf  (raw는 git 제외, 로컬·스토리지에만)
[3] 파서: PDF → 텍스트 → LLM으로 문항 단위 구조화 (JSON)
      ↓
[4] 정규화·태깅: 대학/전형/모집단위/연도/면접유형/평가영역/출처URL/공개여부(actual|example|none)
      ↓
[5] 검수 큐: 사람이 확인한 뒤 DB 반영 (verified 플래그)
      ↓
[6] 앱 DB
```

### 문항 스키마 (핵심 테이블)

```
universities(id, name, region, type[general|junior|teachers|military|police|special], admission_url)
admission_types(id, university_id, name, category[student_record|essay_based|personality|major|english|mmi], interview_weight, notes)
questions(id, university_id, admission_type_id, unit(모집단위/계열), year,
          kind[actual|example|predicted], text, presented_material, intent, rubric, model_answer_hint,
          source_url, source_page, verified bool, created_at)
applicant_profiles(code, label, seed_questions json, answer_frame json)
users(id, email, birth_year, guardian_consent bool, profile_code, target_univ_id, target_admission_id, target_unit, created_at)
user_answers(id, user_id, question_id nullable, question_text, answer_text, feedback json, created_at)  -- 옵트인 저장 시에만
```

### 수집 우선순위
1. 서울대·연세대·고려대·성균관대 (문항카드 가장 풍부, 파서 기준 잡기)
2. 경희대·중앙대·서울시립대·이화여대·한국외대·동국대·인하대 (예시질문형)
3. 서울교대·공주교대·육사 (특수대)
4. 거점국립대 의대·재외국민 특별전형 문항 (부산대 등)
5. 그 외 대학은 평가영역·예시만 수집 → `kind=predicted` 생성 대상

### 파서 규칙
- 대학마다 PDF 구조가 다르므로 `pipeline/parsers/{univ_code}.py` 로 분리. 공통 인터페이스: `parse(pdf_path) -> list[QuestionRecord]`.
- LLM 구조화 시 프롬프트에 "문항 원문을 그대로 옮기되 해설·의도는 요약" 원칙 명시. 출력은 JSON 스키마 강제.
- "인성면접이라 문항 미작성" 같은 문구가 감지되면 `kind=none` 으로 기록하고 평가영역 텍스트만 저장.

## 5. LLM 설계

- 모델: Anthropic API (Claude). 키는 환경변수 `ANTHROPIC_API_KEY`. 클라이언트에 노출 금지 — 서버 라우트에서만 호출.
- **예상질문 생성 프롬프트 입력**: 지원자 유형 템플릿 + 대학·전형 평가영역 + 해당 대학 공개문항 5~10개(있으면) + 사용자 활동 요약. 출력: `[{question, basis: "actual"|"predicted", why_asked, tips}]`.
- **답변 피드백 프롬프트 입력**: 질문 + 사용자 답변 + 대학 평가요소 + 유형별 주의점. 출력: 점수(구조/근거/진정성/길이) + 구체 개선점 3개 + 개선 예시 답변 1개. 예시 답변에는 "그대로 외우지 말고 본인 경험으로 바꾸라"는 안내 포함.
- 프롬프트는 `prompts/*.md` 로 파일 분리하고 버전 관리.
- 응답 캐싱: 같은 대학·전형·유형 조합의 "기본 예상질문 세트"는 캐시. 사용자 개인화 부분만 매번 호출.

## 6. 기술 스택 제안 (확정 전 사용자에게 확인할 것)

- 프론트/서버: **Next.js (App Router, TypeScript)** — 반응형 웹 1개로 PC·모바일 대응
- DB: 개발은 **SQLite**, 배포 시 Postgres 전환 가능하도록 ORM(Drizzle 또는 Prisma) 사용
- 클라이언트 PDF 파싱: `pdfjs-dist` (브라우저 내 처리)
- 로컬 저장: IndexedDB (idb 라이브러리)
- 파이프라인: **Python** (`pipeline/`): requests + pdfplumber/pymupdf + Anthropic SDK
- 배포: Vercel 또는 Cloudflare Pages + 서버리스 API. 정적 부분은 SEO 대상(대학별 기출 페이지가 유입 채널)
- 인증: 이메일 매직링크 (소셜 로그인은 후순위). 생년 입력으로 연령 게이트.

## 7. 화면 구성 (MVP)

1. `/` 랜딩 — "특성화고·검정고시·재수생·해외 출신도 나에게 맞는 면접 준비" 메시지, 대기자 이메일
2. `/univ/[id]` 대학 페이지 — 전형별 면접 유형·반영비율·공개 문항 목록·출처 링크 (SEO용 공개 페이지)
3. `/onboarding` — 유형 선택 → 지원 대학/전형/학과 → 활동 입력(또는 생기부 PDF 클라이언트 파싱)
4. `/practice` — 예상질문 카드 목록(기출/예상 구분) → 답변 입력 → 피드백 → 다시 쓰기. 진행 상황은 로컬 저장
5. `/my` — 내 프로필·저장한 답변(옵트인)·데이터 삭제 버튼(즉시 전량 삭제)
6. `/admin/review` — 파싱된 문항 검수(verified 토글, 수정, 출처 확인)

## 8. 작업 순서 (이 순서대로 진행하고, 각 단계 끝에 실행 방법을 README에 기록)

1. 레포 초기화, 이 문서를 `docs/SPEC.md`로 저장, `CLAUDE.md`에 설계 원칙 1~5 요약
2. `pipeline/` — 서울대 1개 대학 기준으로 수집→파싱→JSON 출력까지 end-to-end 동작 확인
3. DB 스키마 + 시드 로더 (`universities.json`, `profiles/*.json`)
4. 연세대·고려대·성균관대 파서 추가, 검수 UI(`/admin/review`)
5. 대학 공개 페이지 `/univ/[id]`
6. 온보딩 + 예상질문 생성 API
7. 답변 코칭 API + `/practice`
8. 생기부 클라이언트 파싱 (선택 기능)
9. 나머지 대학 수집 확장, 예시질문형 대학 처리
10. 배포 + 랜딩 + 대기자 수집

각 단계는 별도 브랜치/PR로. 파이프라인 결과물(raw PDF)은 `.gitignore`.

## 9. 완료 기준 (Definition of Done, Phase 1)

- 상위 15개 대학 이상에서 최근 3개 연도 문항이 DB에 들어가고 `/univ/[id]`에서 열람 가능
- 7개 지원자 유형 각각 온보딩 → 예상질문 15개 이상 생성 → 답변 피드백까지 동작
- 생기부 PDF를 올려도 네트워크 탭에서 원문이 서버로 전송되지 않음을 확인
- 모든 문항에 `source_url`이 있고, 원문 PDF는 앱 도메인에서 서빙되지 않음
- 데이터 삭제 버튼 클릭 시 서버·로컬 데이터 전량 삭제
- 모바일 화면(375px)에서 모든 화면 사용 가능

## 10. 하지 말 것

- 대학 보고서 PDF를 그대로 업로드·호스팅·다운로드 제공
- 생기부 원문을 서버 로그·DB·LLM 요청 로그에 남기기 (LLM에는 요약만 전송)
